# FairChange audit — 2026-09-09

## Scope

This audit covers the Python workflow, AgentCore payload boundary, persisted approval path, authentication claims, judging evidence, and final-submission requirements.

## Fixed before submission

- Free-form runtime prompts now become bounded ephemeral requests, so their evidence can be validated against the synthetic engagement instead of producing an unsupported request ID after model execution.
- Runtime payloads reject non-objects, empty or unknown fixture IDs, oversized prompts, fixture-ID reuse, and unsafe prompt IDs.
- Assessments now reject unknown decisions, unknown request IDs, empty summaries or evidence, malformed task policy fields, billable defects, and billable included revisions.
- Billable proposed tasks now always require owner review, and runtime payloads reject ambiguous fixture-plus-prompt requests.
- The deterministic assessor rejects unknown request IDs instead of silently treating them as the scope-change fixture.
- Architecture, deployment, judging, and public-demo copy now distinguish Cognito runtime authentication from IAM deployment access and local HMAC test tokens.
- The video documentation now describes the current 4-minute-36-second captioned walkthrough, including the approval gates, authentication boundary, limitations, and public YouTube/Vimeo constraint.
